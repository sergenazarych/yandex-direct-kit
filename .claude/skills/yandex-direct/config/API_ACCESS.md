# Подключение к API Директа

Для работы нужны три вещи: OAuth-приложение, одобренная заявка этого приложения
на доступ к API Директа и токен пользователя, которому доступен рекламный кабинет.
Регистрация приложения и заявка — отдельные шаги; одного токена недостаточно.

Если подключение уже настроено, начните с проверки из [README.md](README.md).
Файл с токеном открывать и выводить не нужно. Если используете уже одобренное
приложение, повторная заявка не нужна: переходите к получению своего токена.

## 1. Создайте OAuth-приложение

Войдите под Яндекс-аккаунтом владельца приложения и откройте
[создание приложения](https://oauth.yandex.ru/client/new/).
Если начинаете с главной страницы OAuth, выберите «Для доступа к API или отладки».

| Что заполнить | Что указать |
|---|---|
| Название сервиса | Например, `Помощник по рекламе — [название компании]` |
| Контактная почта | Ваш действующий адрес для вопросов по приложению |
| Доступ к данным | Найдите `direct:api` и выберите разрешение на использование API Яндекс Директа |

Разрешение `passport:business` нужно для авторизации от имени организации
в Яндекс ID. Для обычного подключения пользовательским токеном достаточно
`direct:api`. Wordstat этим доступом не открывается: он идёт через Search API Yandex Cloud (см. [STUDENT_GUIDE.md](STUDENT_GUIDE.md), раздел «Wordstat»).

После создания сохраните **ClientID**: это идентификатор приложения для заявки и
получения токена. Для выбранного типа приложения адрес возврата уже задан
Яндексом; настраивать свой сайт для получения токена вручную не требуется.
Порядок регистрации: [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-api),
права Директа: [документация Директа](https://yandex.ru/dev/direct/doc/ru/concepts/register).

## 2. Подайте заявку в Директе: ответы по полям

Под тем же аккаунтом откройте
[«Мои заявки» в настройках API](https://direct.yandex.ru/registered/main.pl?cmd=apiCertificationRequestList).
Если страница недоступна, проверьте, есть ли кабинет: Яндекс открывает настройки API, только когда
в кабинете есть хотя бы одна кампания (черновик подходит). При первом входе нажмите
«Получить доступ к API», примите соглашение и откройте «Мои заявки» → новая заявка.
[Условия подачи заявки](https://yandex.ru/dev/direct/doc/ru/access-request).

Ниже ответы на все поля формы «Заявка на получение полного доступа к Яндекс.Директ»
в том порядке, в каком они идут на странице (сверено с формой 06.11.2026). Текст в блоках
копируйте целиком, в квадратных скобках подставьте своё. Если ассистент помогает с заявкой,
он может подставить ваши данные сам: имя, логины, число клиентов.

Перед заявкой подготовьте файл спецификации: без него форма не отправится (поле 11).
Готовый файл — [`zayavka/specifikaciya-prilozheniya.pdf`](zayavka/specifikaciya-prilozheniya.pdf).

### 1. «Введите application_id или выберите из списка»
Выберите в списке своё приложение из шага 1 (название и ClientID).

### 2. «Укажите один или несколько контактов…»
Ваша рабочая почта, на неё придёт ответ по заявке.

### 3. «Данные о компании»: название и сайт
- **Название компании:** название ИП или компании. Если работаете как частный специалист —
  `ИП [Фамилия Имя]` или `Частный специалист [Фамилия Имя]`.
- **Сайт:** сайт компании или ваша страница (портфолио, Telegram-канал). Поле необязательное.

### 4. «Выберите утверждение… Вы:»
| Кто вы | Что выбрать |
|---|---|
| Директолог или агентство, ведёте кабинеты клиентов | «Агентство и автоматизируете работу своих сотрудников с кампаниями клиентов» |
| Ведёте рекламу своего бизнеса | «Прямой заказчик и автоматизируете управление собственными кампаниями» |

Варианты «Рекламное агентство и предоставляете своим клиентам сервисы…» и «Разработчик ПО»
не выбирайте: это про сервисы, которыми пользуются чужие клиенты.

### 5. «Технические данные о приложении»
- **Язык программирования:** `Python`
- **Протокол:** отметьте `JSON`
- **Версия библиотек:**
  ```
  Python 3.11+, стандартная библиотека (urllib, json); openpyxl 3.1 для чтения таблиц Excel
  ```

### 6. «…укажите один или несколько логинов в Директе, для которых оно используется»
Ваш логин в Директе (`ulogin` в адресе кабинета) и логины кабинетов клиентов, каждый с новой строки:
```
[ваш-логин]
[логин-клиента-1]
```

### 7. «Для чего предназначено приложение»
Отметьте **«Автоматизировать регулярную работу по управлению кампаниями в Директе»**.
Остальные пункты не отмечайте.

### 8. «Основные функции приложения»
Отметьте:
- «Получение статистики и отчетов»;
- «Управление кампаниями и объявлениями»;
- «Управление ставками (биддинг)».

«Подбор ключевых слов (использование wordstat)» не отмечайте: Wordstat подключается отдельно,
через Yandex Cloud, а не через API Директа.

### 9. «Какие новые возможности работы с Директом дает ваше приложение пользователям?»
```
Приложение — локальный помощник специалиста по рекламе, который работает через ИИ-ассистента в терминале. Возможности:
- выгружает статистику по кампаниям, группам, объявлениям, фразам и площадкам за выбранный период с конверсиями по выбранным целям Метрики, считает цену конверсии и сравнивает периоды;
- проверяет настройки кампаний по чек-листу (стратегия, бюджет, площадки, корректировки, UTM-метки, расширения) и показывает отклонения;
- создаёт кампанию в РСЯ из заранее проверенной таблицы Excel: группы, фразы, объявления, быстрые ссылки, уточнения, запрещённые площадки, корректировки. Таблица сначала проверяется на лимиты Директа, затем показывается план, и только после подтверждения выполняется запись;
- вносит точечные правки (тексты, ставки, корректировки, минус-фразы, площадки) с показом «было → станет» перед записью;
- ведёт журнал изменений по каждому кабинету.
Приложение работает с [числом] кабинетами: [моим собственным / кабинетами моих клиентов].
```

### 10. «Опишите схему взаимодействия вашего приложения с Директом»
```
1. Схема и последовательность вызовов.
Программа запускается пользователем вручную под конкретную задачу, фоновых и регулярных запусков нет. Все запросы идут последовательно, в один поток (одно соединение).
Типовая последовательность: AgencyClients.get / Clients.get (выбор кабинета, валюта) → Dictionaries.get (регионы, константы; кэш на сутки) → Changes.check (нужно ли обновить локальный кэш) → Campaigns.get, AdGroups.get, Ads.get, Keywords.get, Sitelinks.get, AdExtensions.get (структура) → Reports (статистика).
Запись: чтение текущего состояния → проверка лимитов → показ «было → станет» → подтверждение пользователя → Campaigns.add/update, AdGroups.add, Keywords.add, Ads.add, Sitelinks.add, AdExtensions.add, AdImages.add, BidModifiers.add, KeywordBids.set → повторное чтение и сверка результата.
Частота: десятки запросов за сеанс работы, в среднем до [100–300] запросов в день.

2. Цели методов.
Campaigns, AdGroups, Ads, Keywords — чтение структуры и создание или изменение кампаний по задаче пользователя. Reports — расходы, клики, конверсии по целям, поисковые запросы и площадки. Sitelinks, AdExtensions, AdImages — быстрые ссылки, уточнения и изображения объявлений. BidModifiers, KeywordBids — корректировки и ставки. Dictionaries, Changes, Clients, AgencyClients — справочники, выбор кабинета и обновление кэша. KeywordsResearch — проверка наличия спроса по фразам.

3. Объём данных.
Сейчас: [1–5] кабинетов, до [20] кампаний, до [500] объявлений и [2 000] фраз. В течение года: до [10–20] кабинетов, до [100] кампаний.

4. Учёт ограничений.
Перед запросами проверяется остаток баллов (заголовок Units). Чтение постраничное по LimitedBy, запись пакетами в пределах лимитов методов. Справочники и редко меняющиеся данные кэшируются, актуальность проверяется через Changes.check. Отчёты запрашиваются в офлайн-режиме с ожиданием по заголовку retryIn. Запросы идут в один поток.

5. Обработка ошибок.
Разбираются общая ошибка запроса и ошибки по каждому объекту, частичный успех показывается пользователю отдельно. Временные ошибки чтения повторяются с паузой. Запись после неопределённого результата вслепую не повторяется: программа перечитывает данные и сверяет, чтобы не создать дубли. Ошибки авторизации и нехватки баллов останавливают работу с понятным сообщением. Токен хранится локально, в вывод и журналы не попадает.
```

### 11. «Спецификации, скриншоты интерфейса»
Нажмите «Выбрать файл» и приложите [`zayavka/specifikaciya-prilozheniya.pdf`](zayavka/specifikaciya-prilozheniya.pdf).
В поле «Опишите файл»:
```
Спецификация приложения: назначение, порядок работы с API Директа, используемые методы, учёт ограничений и обработка ошибок, пример вывода программы.
```

### 12. «По возможности предоставьте нам демо-доступ к программе»
Программа локальная, демо-аккаунта нет. Можно оставить поле пустым или указать исходный код:
```
https://github.com/sergenazarych/yandex-direct-kit (открытый исходный код, программа запускается локально)
```

### 13. «Пользовательское соглашение»
Прочитайте оферту («Открыть оферту в новом окне»), выберите «Согласен» и нажмите «Отправить».

### После отправки
Статус и замечания смотрите в «Мои заявки». Яндекс рассматривает заявку до семи дней.
Если её отклонили, исправьте то, что указано в замечаниях, и отправьте снова. Заявка
относится к ClientID: если приложение уже одобрено, каждому пользователю отдельная заявка не нужна.
[Порядок рассмотрения](https://yandex.ru/dev/direct/doc/ru/concepts/register).

## 3. Получите токен и подключите скилл

Для локальной работы можно получить токен вручную. Войдите в браузере под
пользователем, которому доступен нужный рекламный кабинет, и откройте адрес,
заменив `CLIENT_ID` идентификатором своего приложения:

```text
https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID
```

Разрешите доступ. Яндекс покажет токен: сохраните его непосредственно в локальном
`config/.env` как `YANDEX_DIRECT_TOKEN`, через редактор, без передачи в чат.
**ClientID и Client secret не заменяют токен.** Поле `YANDEX_DIRECT_ACCOUNT` и
команды проверки описаны в [README.md](README.md).

Этот способ подходит для собственного скрипта или небольшого числа представителей
одного бизнеса. Для приложения с широкой аудиторией нужен удобный процесс
авторизации пользователей. [Получение токена вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token),
[варианты авторизации Директа](https://yandex.ru/dev/direct/doc/ru/concepts/auth-token).

При ошибке `58` проверьте одобрение заявки именно для ClientID, к которому относится
токен. Остальные ошибки: [ERRORS_AND_LIMITS.md](../references/ERRORS_AND_LIMITS.md).
