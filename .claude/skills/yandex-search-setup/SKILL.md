# Настройка рекламы на поиске

## Прими ядро и выбери структуру

Прими таблицы «Паспорт», «Фразы», «Кластеры», «Минусы» или эквивалентную выгрузку. Свяжи по ID кластер, фразы, регион, посадочную, приоритет, общую формулировку заголовка и область минусов. Сохрани связь с ID, назначенными автором ядра. Строки «отложить» и «исключить» не включай в рабочие ключи. Строки «тестировать» требуют выбранного сценария и доступного бюджета. Отрази судьбу каждого кластера в плане. При неполном ядре подготовь определённую часть, явно отметь пробелы. Для исходного запроса с одним сайтом начни со сбора семантики.

Предложи конкретное число кампаний и объясни, какой результат можно будет измерить при имеющемся спросе, бюджете и географии. Следуй [методике выбора стратегии](references/strategy.md). При нескольких разумных вариантах уточни у клиента только решение, меняющее деньги, охват или цель. Не дроби малый объём по формальному признаку. Самостоятельный бюджет, разная экономика услуги, несовместимые регионы или отдельный эксперимент оправдывают кампанию. Внутри кампании сохрани отдельные группы по смыслу и теплоте. Большой информационный сегмент с подходящей посадочной предложи проверять отдельной кампанией.

## Собери объявление и группу

Собери [карточку объявления по кластеру](references/copy.md). Проверь, что заголовок отвечает на намерение, первая быстрая ссылка ведёт к действию и все ссылки имеют описания.

Для каждого кластера напиши одно объявление. Второе добавляй при осмысленном тесте, укажи различие (например, запись на диагностику против расчёта сметы) и показатель выбора. Если часть ключей нельзя естественно покрыть одним заголовком и обещанием, пересмотри границу кластера. Делай заголовок на языке клиента, с названием услуги и нужным уточнением. Текст отвечает на коммерческий вопрос и ведёт к действию на конкретной странице. Цены, сроки, гарантии, специализацию и территорию бери из подтверждённых условий. Для Б2Б покажи единицу заказа или минимальную партию, если это существенно. Проверь отображаемую ссылку, уточнения, быстрые ссылки и их назначение. Пройди по конечному URL с метками и проверь оффер и следующий шаг на телефоне. Прогноз автотаргетинга зависит от основного заголовка, текста и страницы.

Укажи для каждой группы пять переключателей категорий и три переключателя брендов. В основной кампании на горячий спрос по схеме автора выбери «целевые». «Узкие» оцени отдельно по конкретике продукта и примерам Яндекса. Широкие, альтернативные и сопутствующие проверяй в кампании расширения при наличии подходящей гипотезы и лимита потерь. Бренды выбери явно по задаче. Состав переключателей и проверка записи приведены в [настройке через API](references/launch.md).

## Передай в кабинет и в ведение

Покажи план с кабинетом, услугой, кампаниями, группами, регионами, местами показа, объявлениями, ключами, минусами по уровням, настройками автотаргетинга, стратегией, рабочими целями, бюджетом и статусом запуска. Подготовь черновик или внеси согласованные действия по объёму поручения. Используй штатный клиент Директа и [порядок загрузки](references/launch.md). Отдельно различай локальный план, черновик в кабинете, модерацию и фактические показы.

Для ведения сохрани версию ядра и таблицу «Паспорт запуска» со столбцами: ID кластера, имя и ID кампании/группы/объявлений, регион, роль (основа/тест), категории и бренды, режим ставок, лимит, KPI, ID счётчика и целей, URL, дата/время изменения, фактический статус, срок проверки и критерий решения. Идентификаторы из API заполняй после чтения. Для локального плана оставь ID пустыми. Дай ссылки на таблицу, журнал и доступные карточки кампаний.

## Проверка охвата перед загрузкой

Сопоставь услуги на посадочной с историей запросов, включая отложенные категории. Для каждого исходного кластера укажи группу в кабинете или конкретную причину резерва. Решение отложить группу само по себе не даёт основания минусовать услугу на всю кампанию.

Подними из таблицы «Матрицы» варианты действия и объекта, сопоставь принятые фразы с ключами конкретной группы. При объединении «установка», «установить» и «поставить» проверь, что один заголовок и одна посадочная отвечают на все запросы. Когда варианты требуют разных предложений, отрази основание разделения в паспорте и напиши отдельные объявления. Если в старом ядре есть только исходная маска, отметь пробел и проверь варианты по методике сбора семантики. В сверке показывай число исходных масок, принятых ключей и созданных групп отдельно.

Составь контрольные запросы для каждой продвигаемой услуги с городом, без города, со словами «цена», «стоимость» и «сколько стоит». Проверь их против минусов кампании, группы и ключа с учётом операторов. Для кросс-минуса назови группу-получателя и проверь, что её ключ действительно охватывает каждый нужный запрос. Сохраняй коммерческие уточнения, если маршрутизация не доказана. Отдельно проверь пересечение с соседними кампаниями. Географию из последнего брифа перечитай по ID каждой группы, включая тесты.

Для кампании на одну согласованную посадочную веди объявление и быстрые ссылки на эту страницу. При требовании одинакового URL сверь каждую ссылку с согласованным адресом. При просьбе максимально заполнить заголовок покажи его длину и используй свободное место под подтверждённый аргумент. Подробности см. в [карточке объявления](references/copy.md). После записи перечитай ключи, минусы, географию, тексты и назначения ссылок в кабинете. Повтори проверку контрольных запросов по фактическим настройкам, включая бытовые синонимы с ценовыми уточнениями.
