# Спецификация приложения «Помощник по рекламе в Яндекс Директе»

## 1. Назначение

Локальная программа для специалиста по контекстной рекламе. Работает на компьютере пользователя
и запускается вручную через ИИ-ассистента в терминале (Claude Code, Codex) под конкретную задачу:
выгрузить статистику, проверить настройки, создать кампанию из таблицы, внести правку.
Фоновых и регулярных запусков нет. Финансовые операции (платежи, переводы средств) не выполняются.

Пользователи: специалист и его кабинеты (собственный и кабинеты клиентов, к которым у него
есть доступ представителя или агентский доступ).

## 2. Технические данные

- Язык: Python 3.11+, стандартная библиотека (urllib, json); openpyxl 3.1 для чтения таблиц Excel.
- Протокол: JSON. API Директа v5 (`https://api.direct.yandex.com/json/v501/`); Live v4 только для
  методов без аналога в v5 (GetStatGoals, GetRetargetingGoals, GetClientsUnits, AccountManagement.Get).
- Авторизация: OAuth-токен пользователя, хранится локально в файле настроек вне системы контроля
  версий. Токен не выводится на экран и не записывается в журналы.
- Соединения: запросы выполняются последовательно, в один поток.

## 3. Порядок работы с API

**Чтение.** AgencyClients.get / Clients.get (выбор кабинета, валюта) → Dictionaries.get
(регионы, константы; кэш на сутки) → Changes.check (нужно ли обновить локальный кэш) →
Campaigns.get, AdGroups.get, Ads.get, Keywords.get, Sitelinks.get, AdExtensions.get (структура) →
Reports (статистика в офлайн-режиме).

**Запись.** Чтение текущего состояния → проверка лимитов Директа (длины текстов, число объектов,
размер пакета) → показ пользователю «было → станет» → явное подтверждение пользователя →
Campaigns.add/update, AdGroups.add, Keywords.add, Ads.add, Sitelinks.add, AdExtensions.add,
AdImages.add, BidModifiers.add, KeywordBids.set → повторное чтение и сверка с ожидаемым результатом →
запись в журнал изменений кабинета.

**Создание кампании из таблицы.** Пользователь заполняет таблицу Excel (кампания, группы, фразы,
объявления, быстрые ссылки, уточнения, запрещённые площадки, креативы) и отмечает проверенные строки.
Программа проверяет таблицу на ошибки и лимиты, показывает план и только после подтверждения
создаёт кампанию черновиком. Повторный запуск не создаёт дублей: существующие объекты
определяются по выгрузке кампании. Отправку на модерацию пользователь выполняет сам в интерфейсе.

## 4. Используемые методы

| Сервис | Назначение |
|---|---|
| Campaigns, AdGroups, Ads, Keywords | Чтение структуры, создание и изменение кампаний по задаче пользователя |
| Reports | Расходы, клики, конверсии по выбранным целям, поисковые запросы, площадки |
| Sitelinks, AdExtensions, AdImages | Быстрые ссылки, уточнения, изображения объявлений |
| BidModifiers, KeywordBids | Корректировки ставок и ставки |
| Dictionaries, Changes | Справочники и проверка актуальности кэша |
| Clients, AgencyClients | Выбор кабинета, валюта, ограничения |
| KeywordsResearch | Проверка наличия спроса по фразам |
| Live v4: GetStatGoals, GetRetargetingGoals, GetClientsUnits, AccountManagement.Get | Цели Метрики, цели ретаргетинга, остаток баллов, параметры общего счёта (только чтение) |

## 5. Нагрузка

Десятки запросов за сеанс работы, в среднем до 100–300 запросов в день на пользователя.
Объём: от одного до нескольких десятков кабинетов, до сотни кампаний.

## 6. Учёт ограничений

- Остаток баллов проверяется по заголовку Units; при нехватке работа останавливается с сообщением.
- Чтение постраничное по LimitedBy; запись пакетами в пределах лимитов методов.
- Справочники и редко меняющиеся данные кэшируются; актуальность проверяется через Changes.check.
- Отчёты запрашиваются в офлайн-режиме с ожиданием по заголовку retryIn.
- Один поток, без параллельных запросов.

## 7. Обработка ошибок

- Разбираются общая ошибка запроса и ошибки по каждому объекту; частичный успех показывается отдельно.
- Временные ошибки чтения повторяются с паузой.
- Запись после неопределённого результата (например, ошибка 1000) вслепую не повторяется:
  программа перечитывает данные и сверяет, чтобы не создать дубли.
- Ошибки авторизации (53), отсутствия доступа (58) и нехватки баллов останавливают работу
  с понятным пользователю сообщением.

## 8. Пример вывода программы (сокращённо, данные условные)

Проверка подключения:

```
Связь с API Директа есть.
Кабинет: client-login · валюта RUB · баллы: 64 000 из 64 000
```

План загрузки кампании из таблицы (без записи):

```
Таблица: tablica-kampanii.xlsx
Групп 3 · фраз 21 · объявлений с отметкой «да» 9
Проверка таблицы: ошибок нет.

== План ==
  + кампания «РСЯ - Проект - 06.11» (черновик), стратегия: максимум конверсий, недельный бюджет 7 200 ₽
  + 3 группы, регион Россия без Северного Кавказа
  + 21 фраза, 9 объявлений, 4 быстрые ссылки, 3 уточнения
  + запрещённые площадки: 2 списка
  + корректировки: возраст до 18 и 55+ — не показывать
Запись не выполнялась. Для записи запустите с --apply после проверки плана.
```

Изменение с подтверждением:

```
Кампания 123456789, недельный бюджет:
  было   6 000 ₽
  станет 7 200 ₽
Применить? Запись выполняется только после подтверждения пользователя.
```
