# Корректировки РСЯ после запуска

Используй методику урока Сергея Назарова «Корректировки РСЯ после запуска». Пороги и примеры урока помогают искать аномалии. Решение принимай по данным конкретной кампании. Даты запуска, примеры сегментов и действия из материалов урока служат примерами. Разрешение на запись даёт пользователь для конкретного пакета.

## Определи кабинет, период и цель

Используй установленный или проектный **`yandex-direct`** с `scripts/report.py`. Прочитай его `SKILL.md`, затем используй его команды, конфигурацию OAuth и маршрут выбора `Client-Login`. Порядок поиска и команды собраны в [отчётах API](references/reports.md). Работа с подписками MAX относится к отдельному скиллу.

Найди кампанию по ID или названию и прочитай её свежую карточку. При неоднозначности покажи подходящие кабинеты и ID кампаний. В каждой команде передавай явный `--account`. Определи тип кампании, статус, стратегию, места показа, расписание и часовой пояс, дату старта и последние изменения. Если кампания смешанная, анализируй сетевой трафик отдельно и оценивай область действия каждой правки.

Используй период из запроса. Для свежего запуска смотри дни с начала открутки и помечай неполный день. Для действующей кампании по умолчанию сравни последнюю завершённую календарную неделю с предыдущей. Для контроля изменений сопоставь сопоставимые интервалы до и после записи. Назови фактические даты и учитывай задержку конверсий.

По умолчанию возьми ID из действующей стратегии кампании для сетей, в том числе из пакетной стратегии. Через `report.py --list-goals` уточни названия и доступность этих целей для отчёта. Если пользователь явно выбрал другую бизнес-цель, проверь и укажи её ID. Если стратегию или цель не удалось определить, разберись с трафиком через `--traffic-only` и укажи, каких данных о конверсиях не хватает. При нескольких целях показывай метрики отдельно. Согласуй допустимый CPA, когда вывод зависит от окупаемости. Назови валюту, НДС и модель атрибуции. По умолчанию используй `AUTO`, при расхождении с моделью кампании действуй по правилам `yandex-direct`.

## Пройди по отчётам и сформулируй вывод

Выгрузи базовый отчёт по дням → площадки → регионы → пол и возраст → устройства и ОС → объявления и доступные данные по элементам. Если найдено пересечение аномалий, проверь его отдельным совместным разрезом. Используй [отчёты API](references/reports.md) для полей и выгрузки, [методику урока](references/analysis.md) для диагностики.

Дай резюме за выбранный период и по каждому разрезу. По важным сегментам приведи ID или точное имя, расход и его долю, клики, CPC, CTR, конверсии и CPA по выбранным целям, когда показатели доступны. Укажи, где данных достаточно для решения, где нужно наблюдение и какие разрезы отсутствуют. Предлагай правку только при понятной области действия и ожидаемом результате. Если правки пока не обоснованы, назови показатель и момент следующей проверки.

## Подготовь пакет → получи подтверждение → запиши и проверь

Перед подготовкой правок прочитай [внесение изменений](references/changes.md). Собери поддерживаемые API действия в один пакет с ID плана и покажи его в чате. Для каждого пункта укажи объект и область показа, «было → станет», основание в отчёте и возможную потерю полезного трафика. Отдельно укажи гипотезы, требующие дополнительных данных, и действия, доступные только в интерфейсе.

Для правок, предложенных по результатам анализа, дождись явного подтверждения показанного пакета или его пунктов. При частичном подтверждении выполни только выбранное. После согласования перепроверь исходное состояние, внеси правки за один рабочий заход через штатные команды `yandex-direct` и проверь каждую повторным чтением. Покажи результаты по пунктам и путь к журналу. На старте предложи сравнение открутки в следующий рабочий день. Для действующей кампании оцени эффект на сопоставимом периоде с учётом задержки конверсий.
