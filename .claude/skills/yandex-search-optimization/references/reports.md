# Выгрузки и границы детализации

Используй соседний `yandex-direct` с `scripts/report.py` и `references/REPORTS.md`. Для данных Метрики используй отдельный `yandex-metrika`, если он установлен, либо экспорт отчёта из кабинета Метрики. Команды запускаются из каталога соответствующего клиента. На компьютере ученика без uv вместо `uv run` используй команду Python из ONBOARDING.md. В каждой команде Директа указывай логин. Ниже условные ID. Замени даты на нужный период, путь — на абсолютный путь проекта. Сохраняй одинаковые параметры сравнения.

```bash
uv run scripts/campaigns.py --account LOGIN --campaign 123 --no-cache --json
uv run scripts/report.py --account LOGIN --campaign 123 --list-goals
uv run scripts/report.py --account LOGIN --campaign 123 --period 2026-11-09:2026-11-15 --preset search_queries --goals 456 --attribution AUTO --vat YES --no-cache --csv "/path/to/project/queries.tsv"
uv run scripts/report.py --account LOGIN --campaign 123 --period 2026-11-09:2026-11-15 --preset search_positions --goals 456 --attribution AUTO --vat YES --no-cache --csv "/path/to/project/positions.tsv"
uv run scripts/report.py --account LOGIN --campaign 123 --period 2026-11-09:2026-11-15 --type CUSTOM_REPORT --filter "AdNetworkType EQUALS SEARCH" --fields CampaignId,Date,Impressions,Clicks,Cost,Ctr,AvgCpc,Conversions,CostPerConversion --goals 456 --attribution AUTO --vat YES --no-cache --csv "/path/to/project/days.tsv"
```

Для неизвестной бизнес-цели используй `--traffic-only` и набор полей без конверсионных показателей. Разбирай полные TSV. Для запросов используй SEARCH_QUERY_PERFORMANCE_REPORT. Пресет возвращает Query, MatchedKeyword, MatchType, Criterion, CriterionId, CriterionType, ID кампании и группы, AvgImpressionPosition, AvgClickPosition и AvgTrafficVolume. Сохрани исходную строку рядом со смысловой разметкой. Пустой MatchedKeyword допустим, тип условия определяй по CriterionType. Фильтр сети и Slot в этот отчёт не передавай. Период доступных запросов — до 180 дней. Сверь покрытие по расходу и кликам с поисковым итогом, отметь разницу и «Другие поисковые запросы». По агрегированной строке минус-фразы не формируют. [Отчёт по запросам](https://yandex.ru/support/direct/ru/statistics/library/search-queries) · [Типы отчётов](https://yandex.ru/dev/direct/doc/ru/type).

| Разрез | Поля и проверка |
|---|---|
| Итог, динамика, кластеры | CUSTOM_REPORT с фильтром поиска и CampaignId. Отдельно Date, AdGroupId или CriterionId с CriterionType. Для контрольного итога убери Date и прочие разрезы. |
| География | TargetingLocationId и LocationOfPresenceId, LocationOfPresenceName в CUSTOM_REPORT. Сверь фактический регион с заказами и возможностью обслужить его. |
| Площадки и блоки | Placement с поисковым фильтром. Slot в search_positions. При смешанной кампании проверь карты, галерею и динамические места. Область правки может быть шире анализируемого среза. |
| Аудитория | Gender,Age и отдельно Device,MobilePlatform. При гипотезе запроси совместный срез MobilePlatform,IncomeGrade с AdGroupId и поисковым фильтром. UNKNOWN и «остальные» сохраняй отдельно. |
| Объявления и посадочные | AdGroupId,AdId. Через ads.py свяжи ID с текстом и URL. Сравни конверсию и качество лидов при сопоставимой группе и позиции. Для показанных комбинаций элементов используй детализацию из интерфейса. |
| Время и путь до продажи | Проверь расписание и часовой пояс. В Метрике найди счётчик и нужные цели. Возьми отчёт с сегментом кампании и источника, для выручки используй данные электронной коммерции при передаче покупок. При установленном yandex-metrika доступны counters.sh, goals.sh, conversions.sh и ecommerce.sh. Для часов и посадочных используй совместимый отчёт Метрики. Статусы CRM присоединяй по проверяемому ID клика/заказа и удаляй дубли. |
| Категории и бренды | Для современной разбивки возьми экспорт Мастера отчётов или «Поисковых запросов» с группировками «Категория запроса» и «Упоминание брендов в запросах». Сверь ID, даты, цели и уровень детализации. Старое поле API TargetingCategory не выделяет Narrow. При отсутствии экспорта отчитайся по источнику показа и своей смысловой разметке, явно укажи её происхождение. |

Базовые метрики — показы, клики, расход и доля, CTR, CPC, конверсии каждой цели и CPA. В совместимых отчётах добавь AvgEffectiveBid, Sessions, Bounces, BounceRate, AvgPageviews. Учитывай разницу между кликами, визитами, целевыми визитами и достижениями. Ручная ценность цели в Revenue не доказывает фактическую выручку. В JSON и TSV данной версии клиента денежные поля в миллионных долях валюты, в сводке — в валюте. Проверь единицы и пересчитай один раз. CTR в процентах = клики / показы × 100%, CPC = расход / клики, CPA = расход / целевые конверсии. Ноль конверсий при положительном расходе показывай как «расход без результата», CPA оставь пустым. [Поля API](https://yandex.ru/dev/direct/doc/ru/fields-list) · [Значения и ограничения](https://yandex.ru/dev/direct/doc/ru/report-format).

Средняя позиция показа характеризует состоявшиеся показы на первой странице, позиция клика — только состоявшиеся клики. Меньшее число означает более высокое место. Для общего показателя запроси нужную группировку. Без кликов позиция клика не определена. Показы PREMIUMBLOCK / все показы условия на поиске дают долю спецразмещения среди его показов. Связь двух отчётов — CampaignId, AdGroupId, CriterionId, CriterionType и период. Несколько запросов могут принадлежать одному условию. Доля блока относится к условию, а AvgTrafficVolume не является долей выигранных аукционов. Вывод об ограниченном охвате проверь по динамике, бюджету, региональному спросу и экономике.
