# Кампании в РСЯ: эталонная структура

Раздел для кампаний, которые идут **только в сетях** (РСЯ). При расхождении с общим
[PLAYBOOK.md](PLAYBOOK.md) для таких кампаний действует этот документ: общий
справочник частично написан под поиск и смешанные кампании. Эталон для поиска лежит
отдельно: [SEARCH.md](SEARCH.md).

Источник: урок «Структура кампании в РСЯ» (04.11.2026). Автор подчёркивает: единственно
верных схем нет, структура далеко не главный фактор результата, а эталон нужен как
понятная и простая отправная точка. Отклонение от него — повод спросить «зачем», а не
ошибка само по себе.

## Кампания

| Параметр | Эталон | Как проверить |
|---|---|---|
| Стратегия | «Максимум конверсий» с оплатой за клики (`WB_MAXIMUM_CONVERSION_RATE`) | `campaigns.py --campaign ID` |
| Недельный бюджет | Цена конверсии × 10 конверсий минимум, лучше × 12–15 (при 600 ₽: 6 000 ₽ и выше, в уроке 7 200–9 000 ₽) | расчёт |
| Старт без истории | Начинать с ограничения расхода; когда цена конверсии известна — переходить на среднюю цену конверсии (в уроке около 600 ₽ за подписку) | — |
| Потолок ставки (`BidCeiling`) | 400 ₽: защита от залётных кликов из приложений | карточка кампании |
| Модель атрибуции | Не трогать (`AUTO`) | карточка кампании |
| Процент увеличения бюджета | По умолчанию не трогать; для роста +10…+20%. Яндекс откручивает неравномерно, за ростом следить; масштабировать можно новыми кампаниями | интерфейс |
| Минимальный недельный бюджет | По умолчанию не трогать; если несколько кампаний подряд не набирают клики и конверсии — поднять до 80% бюджета | интерфейс |
| UTM | Всегда, единым форматом (ниже) | `campaigns.py` |
| Персонализация (Нейро, альтернативные тексты) | Выключена (`campaign_write.py personalization --off`). Нейро-тексты тестировать отдельно, в Мастере кампаний на малом бюджете | `ALTERNATIVE_TEXTS_ENABLED` |
| Минус-фразы кампании | Не добавлять; в РСЯ минусуются площадки | — |
| Запрещённые площадки | Минусовать на старте списками: базовый, GDZ/DSP/VPN (файлы в `templates/blocked/`) | `campaigns.py` |
| Корректировки | Возраст до 18 и 55+ на −100%, если проект не для этой аудитории. Только полные: частичные не нужны | `bids.py modifier list` |

UTM-метка (единый формат):

```
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}.{device_type}.{region_name}.{retargeting_id}&source={source_type}.{source}
```

### Почему частичные корректировки — ошибка
«−35% на мужчин 45–54» не убирает 35% аудитории. Он снижает цену конверсии для сегмента:
600 ₽ × 0,65 = 390 ₽. Кампания не отказывается от сегмента, а ищет в нём конверсию дешёвой
ставкой, и приходят дешёвые клики по паре рублей, которые не конвертируются. Это частая
ошибка в аудитах. Яндекс определяет пол и возраст неточно, поэтому отрезанный сегмент всё
равно может попадать в воронку; дальше решения принимаются по накопленной статистике.
Отрезать сегмент нужно командой `−100%` (`BidModifier = 0`), остальное оставлять как есть.

## Группа

- Гео: нужное; если кручусь на всю Россию — исключаю Северный Кавказ.
- Ключевые фразы: несколько, максимально широких, либо точечные по воронке. Большой список
  не нужен: после предзапуска Яндекс сам находит аудиторию.
- Автотаргетинг выключен. За раз проверяется один формат таргета; нужен автотаргетинг —
  отдельная кампания без ключей. Общее правило скилла «автотаргетинг — только узкие запросы»
  относится к поиску и в РСЯ не применяется.
- Интересы и привычки не используются.
- Офферный ретаргетинг выключен (чтобы не догонять тех, кого уже заминусовали). Ретаргет — это
  отдельная кампания.

## Объявления

- В комбинаторном объявлении можно до 7 заголовков, до 3 текстов, до 5 креативов.
- **Новый проект или нужен контроль над комбинациями:** минимум — 1–2 заголовка, 1 текст,
  1 креатив. **Работающий проект с новым углом:** можно заполнить объявление по максимуму и
  дать алгоритму разбираться.
- Если заголовков два, они очень похожи и отличаются концовкой («…от фейковых заявок в проектах» /
  «…от спама и фрода в проекте»). Так при перетасовке не рвётся смысл и не приходит другая
  аудитория. Заголовки релевантны лендингу и его первому экрану и не расходятся между собой.
- **Три объявления в группе**, затем группа дублируется целиком (всего 3 группы). Между группами
  меняются только картинки.
- Кнопка: в уроке рекомендована релевантная воронке («Подписаться» для Telegram- и Max-каналов,
  «Зарегистрироваться» для регистраций). **Решение автора для скилла: оставляем кнопку по умолчанию
  («Узнать больше»)**; при необходимости пользователь сам выделяет все объявления в кабинете и
  заменяет название разом. API комбинаторных объявлений кнопку не принимает.
- Карусели — отдельная тема.

## Дополнения

Добавляются всегда.

- **Быстрые ссылки.** В лид-магнитной воронке первая ссылка — призыв, остальные — связанная
  серия, где каждая продолжает предыдущую как точечные крючки. Пример одной мысли на четыре
  ссылки: «Получи видеоразбор в Telegram» → «Избавься от спама и ботов» → «В своих проектах в
  Директе» → «И наконец приводи продажи». Для понятного продукта вместо воронки идут конкретные
  выгоды **с конкретикой**, а не размытые «быстро» и «качественно»: «Монтаж кровли за 10 рабочих
  дней на вашем участке после замера». Лимит: заголовок 30 символов, описание 60.
- **Уточнения** — маркеры «для кого это» («Статья для директологов», «Маркетологов»,
  «И специалистов по трафику»). Лимит 25 символов.
- **Промоакция** — всегда. Даже если дублирует заголовок: тип «Бесплатно» или «Подарок»; то
  же видеоразбор, что на лендинге, мелькает и в промоакции и занимает место в объявлении.
  Описание до 35 символов, обещание должно быть на лендинге. В API нет метода — Библиотека →
  Промоакции, затем привязка в настройках кампании.

Через API быстрые ссылки и уточнения привязываются к объявлениям; «на всю кампанию» это
задаётся в интерфейсе (см. [TABLE_LOADER.md](TABLE_LOADER.md), «Что делается вручную»).

## Как это воплощено в скилле

- Шаблон `templates/tablica-kampanii.xlsx` собран по эталону: 3 группы-дубля по 3 объявления,
  2 близких заголовка, 1 текст, креативы по группам, быстрые ссылки одной мыслью, уточнения
  «для кого», промоакция, UTM, два файла площадок.
- `table_loader.py` сам создаёт кампанию с этой стратегией, добавляет площадки, UTM,
  корректировки возраста, выключает персонализацию, привязывает ссылки и уточнения. Он же
  печатает «Замечания по эталону РСЯ» (недостаточный бюджет, не три группы, разные группы,
  частичные корректировки и т. п.). Замечания ничего не блокируют.
- Автотаргетинг у групп ЕПК может появляться остановленным; перед запуском проверьте, что он
  не включён.

## Этап подготовки таблицы

Тексты в таблицу попадают из заранее проработанных материалов, а не придумываются при заполнении:

1. Паспорт проекта (`pasport-proekta`): аудитория, главное сообщение, нецелевой спрос.
2. Стратегия запуска (`vybor-strategii-zapuska`): РСЯ или другой формат, цель обучения, бюджет.
3. Первый экран лендинга (`usilitel-pervogo-ekrana`): заголовки объявлений должны быть
   релевантны ему.
4. Таблица: заголовки по правилу «близкие по смыслу», быстрые ссылки как серия по воронке,
   уточнения «для кого», промоакция.
5. Картинки (`rsya-creative-prompts`): заголовок берётся из таблицы объявлений.

Готового генератора быстрых ссылок, уточнений и промоакции нет: их пишет специалист или
ассистент по правилам этого раздела. Загрузчик проверяет только формальные признаки (число,
длины, наличие), а не качество формулировок.
