# Сценарий настройки: инструкция для ассистента

Этот файл для ИИ-ассистента (Claude Code, Codex). Ученик открыл репозиторий и попросил
начать или продолжить настройку. Ваша задача — провести его по этапам ниже, от пустого
компьютера до первой кампании в РСЯ, загруженной из таблицы.

## Как вести ученика

- Ученик — директолог или маркетолог, не программист. Говорите по-русски, просто и коротко.
  Один шаг за раз: что сделать, где нажать, что должно получиться. Длинный список сразу не выдавайте.
- Всё, что можно сделать командой, делайте сами: проверки, копирование файлов, запуск скриптов.
  В браузере (Яндекс OAuth, Директ, Yandex Cloud, Метрика) действует ученик, вы подсказываете.
  Если у вас есть встроенный браузер и ученик просит, можете открывать страницы и показывать,
  куда нажать. Пароли, регистрации, платёжные данные и согласия с условиями вводит и принимает ученик.
- После каждого этапа запускайте проверку из этого файла и показывайте результат.
  Без успешной проверки к следующему этапу не переходите.
- Прогресс записывайте в `my/progress.md`: какой этап пройден, дата, что осталось
  (ClientID, дата подачи заявки, логин кабинета и т. п., **без токенов и ключей**).
  В начале каждой сессии сначала прочитайте этот файл и продолжайте с незавершённого этапа.
- Если что-то пошло не так, сначала посмотрите таблицу [частых ошибок](#частые-ошибки),
  затем `config/STUDENT_GUIDE.md` и справочники скилла.

## Железные правила

1. **Секреты не проходят через чат.** Не просите прислать токен или ключ, не открывайте и не
   выводите `config/.env`, не подставляйте секреты в команды. Ученик вставляет их в файл сам,
   в редакторе. Если ученик всё же прислал токен или ключ в чат, не используйте его: попросите
   отозвать и выпустить новый.
2. **Запись в кабинет — только после «да».** Любая записывающая команда сначала запускается без
   `--apply`. Покажите план, дождитесь явного согласия ученика и только потом повторите с `--apply`.
3. **Кампания создаётся черновиком.** Отправлять на модерацию и запускать её решает ученик,
   в интерфейсе Директа.
4. Не меняйте файлы скилла (`.claude/skills/…`), если ученик об этом не просит. Его рабочие
   файлы лежат в `my/`.

## Обозначения

- `SKILL` — папка `.claude/skills/yandex-direct`. Все команды запускаются из корня репозитория.
- `PY` — команда Python. В Windows это `py`, в macOS и Linux — `python3`. Выясните её на этапе 0
  и дальше подставляйте сами. Если установлен `uv`, подойдёт и `uv run`.

Пример: `PY SKILL/scripts/whoami.py` в Windows — это `py .claude/skills/yandex-direct/scripts/whoami.py`.

Перед работой с Директом прочитайте `SKILL/SKILL.md`. Перед этапом 5 прочитайте
`SKILL/references/RSYA.md` и `SKILL/references/TABLE_LOADER.md`.

## Этап 0. Знакомство и проверка компьютера

1. Коротко объясните план: четыре этапа (компьютер → API Директа → Wordstat → первая кампания),
   и что заявка на API Директа рассматривается до 7 дней. Спросите:
   - есть ли кабинет Директа и хотя бы одна кампания (черновик подходит);
   - подана ли уже заявка на API (если да — с какого числа ждёт);
   - есть ли аккаунт Yandex Cloud;
   - для какого проекта будет первая кампания в РСЯ: сайт или лендинг, счётчик Метрики, цель.
2. Проверьте Python: `py --version` или `python3 --version`. Нужна версия 3.11 и новее.
   Если Python нет, подскажите установку (python.org; в Windows отметить «Add python.exe to PATH»)
   и проверьте ещё раз.
3. Установите библиотеку для таблиц: `PY -m pip install -r requirements.txt`.
4. Создайте `my/` и `my/progress.md`, если их нет.
5. Создайте `SKILL/config/.env` копией `SKILL/config/.env.example`, если файла ещё нет
   (копирование файла, без открытия и без вывода содержимого).

**Проверка:** `PY --version` ≥ 3.11, `PY -c "import openpyxl"` без ошибок, файл `SKILL/config/.env` существует.

## Этап 1. API Директа: приложение и заявка

Ведите по `SKILL/config/STUDENT_GUIDE.md`, шаги 1–2.

1. Ученик создаёт приложение на https://oauth.yandex.ru/client/new/ с доступом `direct:api`
   и присылает **ClientID** (это не секрет, его можно писать в чат). Запишите ClientID в `my/progress.md`.
2. Ученик подаёт заявку: https://direct.yandex.ru/registered/main.pl?cmd=apiCertificationRequestList
   → «Мои заявки» → новая заявка с этим ClientID. Ответы на все вопросы формы по порядку — в шпаргалке
   `SKILL/config/zayavka/kak-zapolnit-zayavku.md` (для ученика есть PDF рядом). Спросите у ученика
   недостающее: ИП или имя, сайт, ведёт ли он клиентов, логины кабинетов, примерное число кабинетов
   и кампаний. Подставьте это в ответы и выдайте их по вопросам формы, сверху вниз, блоками для
   копирования. Отмечать в чекбоксах только то, что указано в шпаргалке: лишнего не обещайте.
   В вопросе 11 прикладывается `SKILL/config/zayavka/specifikaciya-prilozheniya.pdf`
   (подскажите ученику полный путь к нему на его компьютере).
3. Запишите дату подачи. Пока заявка на рассмотрении, переходите к этапу 3 (Wordstat от неё не зависит)
   и к подготовке таблицы на этапе 5.

**Проверка:** в «Мои заявки» статус «Одобрена». До одобрения этап 2 не начинайте: токен выпустится,
но API ответит ошибкой 58.

## Этап 2. Токен Директа и первая проверка

1. Дайте ученику ссылку с его ClientID:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID>`.
   Открывать её нужно под тем аккаунтом, чей кабинет будет вести ученик.
2. Ученик открывает `SKILL/config/.env` в редакторе и вставляет токен в строку `YANDEX_DIRECT_TOKEN=`.
   Логин кабинета (`ulogin` в адресе кабинета) — в `YANDEX_DIRECT_ACCOUNT=`. Если кабинет один, строку
   можно оставить пустой. Логин не секрет, его ученик может написать в чат.
3. Запустите проверки:
   ```
   PY SKILL/scripts/whoami.py
   PY SKILL/scripts/campaigns.py
   ```

**Проверка:** `whoami.py` пишет «Связь с API Директа есть» и показывает логин и баллы,
`campaigns.py` выводит кампании кабинета. Если ученик ведёт клиентов, разберите раздел
«Чужие кабинеты» в `STUDENT_GUIDE.md` (шаг 5) и проверьте `whoami.py --account ЛОГИН_КЛИЕНТА`.

## Этап 3. Wordstat (Yandex Cloud)

Ведите по разделу «Wordstat → Как получить ключ» в `STUDENT_GUIDE.md`. Токен Директа Wordstat не открывает.

1. Ученик входит на https://console.yandex.cloud. Если облака или платёжного аккаунта нет,
   консоль предложит их создать: это делает ученик, вы объясняете. Запросы к Wordstat платные,
   тарифы смотрите в разделе «Тарифы» документации Search API.
2. Каталог (обычно `default`) → Identity and Access Management → «Создать сервисный аккаунт».
   Имя, например, `wordstat-direct`. Роль — **только** `search-api.webSearch.user`.
3. Аккаунт → «Действия» → «Создать новый ключ» → «Создать API-ключ».
   Область действия — **только** `yc.search-api.execute`.
   Секрет показывается один раз: пусть ученик сразу вставит его в `SKILL/config/.env`,
   в строку `YANDEX_WORDSTAT_API_KEY=`.
4. ID каталога виден в адресе консоли (`/folders/<ID>/`). Его ученик может прислать в чат или сам
   вписать в `YANDEX_WORDSTAT_FOLDER_ID=`. Это не секрет, но файл `.env` вы не открываете:
   если ученик прислал ID, попросите вписать его самостоятельно.
5. Проверьте на фразе из ниши ученика:
   ```
   PY SKILL/scripts/wordstat.py top --phrase "фраза" --limit 20 --region 225
   PY SKILL/scripts/wordstat.py dynamics --phrase "фраза" --from <ГГГГ-ММ-01 полгода назад> --period month
   ```

**Проверка:** `top` показывает число запросов за 30 дней и список фраз, `dynamics` — помесячную частоту.

## Этап 4. Итог по ключам

Покажите сводку: Директ подключён (логин), Wordstat подключён. Отметьте это в `my/progress.md`.
Напомните про безопасность: `.env` никому не отправлять и не выкладывать, а при утечке отозвать ключи.

## Этап 5. Первая кампания в РСЯ из таблицы

Эталон кампании — `SKILL/references/RSYA.md` (урок «Структура кампании в РСЯ»), порядок работы
с загрузчиком — `SKILL/references/TABLE_LOADER.md`. Отклонение от эталона — повод спросить «зачем»,
а не ошибка.

1. **Рабочая папка.** Скопируйте `SKILL/templates/tablica-kampanii.xlsx` и папку `SKILL/templates/blocked/`
   в `my/<проект>/`. Списки площадок должны лежать рядом с таблицей.
2. **Данные проекта.** Сначала посмотрите `my/<проект>/`: паспорт, стратегию, первый экран.
   Тексты для таблицы берутся из этих материалов, а не придумываются на ходу (`RSYA.md`, «Этап подготовки
   таблицы»). Если материалов нет, предложите ученику пройти их скиллами курса и сохранить результат
   в `my/<проект>/`:
   - `pasport-proekta` — паспорт проекта (`my/<проект>/pasport-<клиент>.md`): аудитория, главное сообщение, нецелевой спрос;
   - `vybor-strategii-zapuska` — подтвердить, что РСЯ подходит, и выбрать цель обучения;
   - `usilitel-pervogo-ekrana` и `auditor-posadochnyh` — первый экран и проверка посадочной:
     заголовки объявлений должны быть ему релевантны.
   Если ученик торопится, можно взять минимум прямо в диалоге: оффер, аудитория, адрес лендинга,
   ориентир цены конверсии.
   - Счётчик Метрики и ID цели: Метрика → нужный счётчик → «Настройки» → «Цели». Цель — целевое действие
     (заявка, подписка), не автоцель.
   - Недельный бюджет: цена конверсии × 12 (минимум × 10).
3. **Заполнение таблицы.** Заполните листы по эталону: «Кампания», «Группы» (3 группы-дубля),
   «Фразы» (несколько широких), «Объявления» (по 3 в группе, 2 близких заголовка, 1 текст),
   «Быстрые ссылки» (4 ссылки одной мыслью по воронке), «Уточнения» («для кого»), «Промоакции», «Креативы».
   В шаблоне стоят примеры из урока, а ссылки заменены заглушкой `ваш-сайт.ru`: загрузчик не пропустит
   таблицу, пока ученик не впишет свои адреса. Заполнять можно через openpyxl (сохраняйте форматирование)
   или вместе с учеником в Excel. Тексты согласуйте с учеником, лимиты длины проверит загрузчик.
4. **Картинки.** Нужны файлы `creo-1.jpg`, `creo-2.jpg`, `creo-3.jpg` (JPG или PNG от 450×450) рядом с таблицей,
   по одной картинке на группу. Нет картинок — помогите написать промпты скиллом
   `.claude/skills/rsya-creative-prompts` (прочитайте его `SKILL.md`), картинки ученик генерирует сам.
5. **Проверка ученика.** Ученик открывает таблицу и ставит «да» в колонке «Проверено» у каждого объявления,
   которое готово к загрузке. Объявления без «да» загрузчик пропускает.
6. **План без записи:**
   ```
   PY SKILL/scripts/table_loader.py my/<проект>/tablica-kampanii.xlsx --account ЛОГИН
   ```
   Исправляйте «ОШИБКИ В ТАБЛИЦЕ», пока их не останется. «Замечания по эталону РСЯ» объясните ученику:
   они не блокируют.
7. **Запись.** Покажите план, получите явное «да» и запустите ту же команду с `--apply`.
   Кампания создаётся черновиком. Запишите её ID в `my/progress.md`. Повторный запуск
   с `--campaign ID --apply` дублей не создаёт и дозагружает недостающее.
8. **Ручные шаги в интерфейсе** (их нет в API): промоакция (Библиотека → Промоакции, затем привязка
   в настройках кампании), при желании быстрые ссылки и уточнения на уровне кампании, кнопка объявления.
   Список — раздел «Что делается вручную» в `TABLE_LOADER.md`.
9. **Сверка:** `PY SKILL/scripts/campaigns.py --account ЛОГИН --campaign ID`. Пройдитесь с учеником
   по эталону: стратегия, бюджет, потолок ставки, UTM, площадки, корректировки возраста, автотаргетинг выключен.

**Проверка:** кампания видна в кабинете черновиком, сверка с эталоном пройдена. Отправить на модерацию
ученик решает сам.

## Этап 6. Что дальше

Расскажите, что теперь можно просить у ассистента обычными словами: «покажи расход и конверсии за неделю»,

## Частые ошибки

| Что видно | Причина | Что делать |
|---|---|---|
| `py` / `python3` не найден | Python не установлен или не добавлен в PATH | Установить с python.org, в Windows отметить «Add python.exe to PATH», перезапустить терминал |
| `No module named openpyxl` | Не установлена библиотека | `PY -m pip install -r requirements.txt` |
| `Токен не задан` | Нет `config/.env` или пустая строка токена | Этап 2, п. 2 |
| Директ: код 58 | Заявка ещё не одобрена именно для этого ClientID | Ждать одобрения, сверить ClientID в ссылке токена |
| Директ: код 53 | Токен неверный или отозван | Получить токен заново по ссылке |
| Директ: нет доступа к кабинету клиента | Аккаунт не добавлен представителем | Раздел «Чужие кабинеты» в `STUDENT_GUIDE.md` |
| Wordstat: «Ключ не задан» | Пустая строка `YANDEX_WORDSTAT_API_KEY` | Этап 3, п. 3 |
| Wordstat: 401 | Ключ неверный или отозван | Создать новый API-ключ |
| Wordstat: 403 | У аккаунта нет роли `search-api.webSearch.user` или у ключа не та область | Проверить роль в каталоге и область `yc.search-api.execute` |
| Wordstat: 429 | Превышена квота | Подождать и повторить |
| Загрузчик: «ссылка-заглушка ваш-сайт.ru» | В таблице остались адреса из шаблона | Вписать адрес своей страницы |
| Загрузчик: «не заполнено Счётчик/Цель» | Не указаны ID из Метрики | Этап 5, п. 2 |
| Загрузчик: «нет хеша и нет файла рядом» | Картинки не лежат рядом с таблицей | Положить `creo-N.jpg` в `my/<проект>/` |
| Директ: ошибка 1000 при записи | Временный сбой, запись могла пройти | Загрузчик сам перечитывает кабинет; повторить запуск с `--campaign ID` |
