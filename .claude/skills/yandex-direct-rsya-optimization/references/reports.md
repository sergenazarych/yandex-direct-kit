# Отчёты через API Яндекс Директа

## Подключение и чтение

Используй соседний каталог `.claude/skills/yandex-direct` с `scripts/report.py`, `scripts/bids.py`, `scripts/ads_write.py` и `references/REPORTS.md`. Запускай команды из этого каталога через `uv run` или доступный Python 3.11+. На Windows подходит `py -3`, в macOS и Linux — `python3`.

```sh
uv run scripts/accounts.py --search "название или домен"
uv run scripts/whoami.py --account example
uv run scripts/campaigns.py --account example --campaign 123 --no-cache --json
uv run scripts/report.py --account example --campaign 123 --list-goals
```

Используй действующее подключение базового скилла. Секреты читает его клиент. При ошибке доступа используй `whoami.py` и инструкцию `config/README.md`. Для настройки целей и атрибуции смотри `references/REPORTS.md` базового скилла. Нужную цель аналитики передавай явно в `--goals`; это параметр отчёта.

## Матрица выгрузок

Для всех строк ниже используй `CUSTOM_REPORT` и фильтр `AdNetworkType EQUALS AD_NETWORK`. При смешанных местах показа уточни по настройкам и разрезам, покрывает ли сетевой фильтр весь искомый трафик и требуется ли уточнение, например по Картам. Для групповых разрезов держи `CampaignId` и ID нужных сущностей. Для сводки за весь период запроси также строку с `CampaignId` и метриками, без `Date`. Такой итог позволяет корректно читать средние и долю расхода.

| Разрез | Поля группировки после `CampaignId` | Проверка |
|---|---|---|
| Динамика | `Date` | Показы, темп расхода, CPC, ставка, CTR, конверсии и CPA. |
| Площадки | `Placement` | Доля расхода, CPC, CTR и результат. При необходимости уточни внешнюю сеть через `ExternalNetworkName`, затем рассчитай показатели по площадке целиком. |
| Города и регионы | `LocationOfPresenceId,LocationOfPresenceName` | Фактическое местонахождение. Для геоправки добери отдельный разрез с `AdGroupId,TargetingLocationId,LocationOfPresenceId`. |
| Аудитория | `Gender,Age` | Расход, объём конверсий и CPA. `UNKNOWN` оставь отдельной строкой. |
| Устройства | `Device,MobilePlatform` | Тип устройства, ОС, объём, CPA, отказы. При необходимости сравни устройства без разбивки по ОС. |
| Объявления | `AdId` или `AdGroupId,AdId` | Итог по каждому объявлению. Содержимое читай через `ads.py`, чтобы привязать наблюдение к объекту. |
| Пересечение | `Placement,TargetingLocationId,AdGroupId,AdId,Device,MobilePlatform,Gender,Age` | Запрашивай после обнаружения аномалии на конкретных площадках. Начинай с минимального набора измерений. При необходимости добавь фактический регион. |

Базовые метрики для всех разрезов: `Impressions,Clicks,Cost,Ctr,AvgCpc,AvgEffectiveBid,Bounces,Sessions,BounceRate,AvgPageviews,Conversions,CostPerConversion`. CPA и конверсии выгружай по одобренным бизнес-целям. Если цель ещё выбирают, используй `--traffic-only` с полями до `Conversions`. Ставка, отказы и глубина зависят от типа кампании и доступности данных Метрики в Direct Reports. При недоступном показателе сохрани остальные и назови пробел.

Пример вывода по площадкам. Для остальных разрезов замени группировки из таблицы. Для динамики используй `--order-by Date:asc`.

```sh
uv run scripts/report.py --account example --campaign 123 --period 2026-11-16:2026-11-22 --type CUSTOM_REPORT --filter "AdNetworkType EQUALS AD_NETWORK" --fields CampaignId,Placement,Impressions,Clicks,Cost,Ctr,AvgCpc,AvgEffectiveBid,Bounces,Sessions,BounceRate,AvgPageviews,Conversions,CostPerConversion --goals 456 --attribution AUTO --vat YES --order-by Cost:desc --no-cache --csv "placements.tsv"
```

Передай абсолютный путь к TSV в рабочей папке пользователя, чтобы выгрузка не попала в каталог `yandex-direct`. Смотри полный TSV, а не только топ строк в сводке или `--json`. Для сравнения повтори выгрузку с другим периодом и сохрани в другой файл. Одинаково задай цели, атрибуцию, фильтры, валюту и НДС. Команда базового скилла обрабатывает ожидание отчёта и пагинацию. Проверь фактическое покрытие, размеры выгрузок и ошибки отдельно по каждому разрезу.

В TSV и JSON документированные денежные поля представлены в миллионных долях валюты аккаунта. Дели на 1 000 000 один раз. При агрегации пересчитывай CPC = расход / клики, CTR = клики / показы × 100%, CPA цели = расход / конверсии этой цели, долю отказов = отказы / визиты × 100%. Сохраняй глубину и эффективную ставку из отчёта нужного уровня. Конверсии по разным целям и моделям показывай отдельно. Прочерк, пропуск и нулевой знаменатель означают, что соответствующий показатель не оценён. [Поля Reports](https://yandex.ru/dev/direct/doc/ru/fields-list) · [Формат и значения](https://yandex.ru/dev/direct/doc/ru/report-format).

## Элементы комбинаторных объявлений

Reports API позволяет измерить результат по `AdId`. Список заголовков, текстов и изображений из `Ads.get` показывает состав объявления. Для фактически показанных комбинаций используй выгрузку Мастера отчётов с номером объявления и группировками по заголовку, тексту, изображению или видео. Сверь кабинет, периоды, фильтр сетей, цели, атрибуцию и НДС. Для связи варианта с площадкой, регионом или демографией эти поля должны быть в той же выгрузке. Совпадение `AdId` между отдельными отчётами не восстанавливает распределение показов по комбинациям. Если выгрузки нет, разбери уровень объявления и укажи, какие показатели по комбинациям остаются недоступны. Для Мастера кампаний проверь, доступны ли `AdGroupId` и `AdId` в принципе. [Справка по комбинаторным объявлениям](https://yandex.ru/support/direct/ru/unified-performance-campaign/create-comb-ad).
