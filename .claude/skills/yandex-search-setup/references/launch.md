# Настройка и проверка через штатный API

Найди установленный или проектный `yandex-direct` с `scripts/campaign_write.py`, `keywords_write.py` и `references/AUTOTARGETING.md`. В ученическом наборе он лежит рядом в `.claude/skills/yandex-direct`. Используй текущую конфигурацию подключения. Ниже условные логин и ID, команды запускаются из соответствующего API-скилла. На компьютере ученика без uv вместо `uv run` используй команду Python из ONBOARDING.md.

1. Найди кабинет через `uv run scripts/accounts.py --search "домен"`, проверь логин через `whoami.py --account LOGIN`. Счётчик и ID цели возьми из Метрики или из паспорта ученика. Если установлен отдельный `yandex-metrika`, используй его `counters.sh` и `goals.sh`. Для существующей кампании проверь счётчик через `campaigns.py` и доступные цели через `report.py --account LOGIN --campaign ID --list-goals`. Сверь бизнес-событие, ID и доступность оптимизации. Разрешённые цели отчёта могут отличаться от выбранной цели стратегии.
2. Спланируй ЕПК через `campaign_write.py create`, для существующей — сначала `campaigns.py --account LOGIN --campaign ID --no-cache --json`. Передавай `--account` во все команды кабинета. Для выдачи проверь SearchResults=YES, поисковую стратегию и Network=SERVING_OFF. В известной версии клиент требует полного выбора SearchResults, ProductGallery, Maps, SearchOrganizationList. Для обычной выдачи три последних выключены. При создании DynamicPlaces следует за SearchResults, проверь фактические места после создания и ограничения интерфейса для конкретной задачи. Проверь расписание, часовой пояс, расширенное гео с учётом выезда/доставки, валюту и НДС, стратегию, бюджет, цели и счётчик. Если требуется строго ограниченное размещение, а клиент не позволяет его задать, отметь оставшийся шаг до активации. [Настройка кампании](https://yandex.ru/support/direct/ru/unified-performance-campaign/create-campaign).
3. Создай группы через `ads_write.py group create`, ключи через `keywords_write.py keyword add`, согласованные минусы на соответствующих уровнях, объявления через `ads_write.py ad create`, дополнения через `extensions.py`. Для синтаксиса текущей версии проверь `--help` и `references/CHANGES.md`. При нескольких ссылках проверь UTM, сохранение исходной строки параметров и работу разметки после редиректа. Переноси исходные минусы только в область, проверенную после окончательного разбиения по кампаниям. Для существующего списка при добавлении сохраняй прежние исключения. Штатный `table_loader.py` ориентирован на РСЯ и может добавить возрастные корректировки и исключения площадок. Используй пообъектные команды для поиска.
4. Настрой автотаргетинг по факту каждой группы. Автотаргетинг обязателен, по умолчанию могут быть включены все категории. Оставь минимум одну с прогнозом показов. Категории и упоминания брендов сочетаются по «И». Ключи работают параллельно с автотаргетингом. Ограничения категорий действуют на автоподбор, поэтому проверь брендовые ключи и минус-фразы отдельно. По примерам запросов в интерфейсе проверь, как Яндекс понимает конкретные текст и посадочную. [Правила ЕПК](https://yandex.ru/support/direct/ru/impression-criteria/autotargeting-upc) · [Категории и бренды](https://yandex.ru/support/direct/ru/impression-criteria/autotargeting).

| Переключатель API | Решение для предложения |
|---|---|
| Exact — целевые | Запрос непосредственно соответствует услуге. Основа для горячей кампании. |
| Narrow — узкие | Человек уточнил характеристику, модель или подвид. Проверь, что именно эту потребность обслуживает клиент. |
| Broader — широкие | Запрос шире предложения. Проверяй расход и ценность дополнительного охвата отдельно. |
| Alternative — альтернативные | Пользователь ищет другой способ решить задачу. Объявление и страница должны объяснить замену. |
| Accessory — сопутствующие | Человек ищет связанный продукт. Нужен обоснованный путь от этого интереса к продаже услуги. |
| WithoutBrands / WithAdvertiserBrand / WithCompetitorsBrand | По каждой группе явно укажи, нужны ли запросы без бренда, со своим брендом, с конкурентом. Для привлечения нового небрендового спроса оставь WithoutBrands. |

Пример плана без записи для основной группы, где согласован только целевой небрендовый автоподбор. Сначала найди ID автоматического условия в группе. При наличии обновляй именно этот ID. При отсутствии используй `autotargeting add --group ID` с полным набором опций.

```bash
uv run scripts/keywords.py --account LOGIN --group 456 --autotargeting --no-cache --json
uv run scripts/keywords_write.py autotargeting set --account LOGIN --keyword 789 --category Exact=YES --category Narrow=NO --category Broader=NO --category Alternative=NO --category Accessory=NO --brand WithoutBrands=YES --brand WithAdvertiserBrand=NO --brand WithCompetitorsBrand=NO
```

Задавай все пять значений и для новой группы три опции брендов. Ручную ставку по автоусловию проверяй отдельно. Рекомендацию базового клиента «только узкие» замени выбранным сценарием проекта. Для теста расширения обычно используй группы по проверяемой категории с отличимой в отчёте гипотезой. Настройки могут применяться к показам до суток. При смене мест показа перечитай их ещё раз.

5. Отработай план штатными dry-run командами. Запись выполняй в рамках явного поручения по показанной конфигурации и бюджету. Если поручено создать черновик, сохрани его черновиком. Фиксируй соответствие локальных ID присвоенным Яндексом. При таймауте или частичной записи сначала перечитай кабинет, затем повтори только отсутствующую операцию. Перед активацией сверь после чтения тип кампании, места показа, регионы, бюджеты, цели, фразы, минусы, все категории, бренды, объявления и ссылки. Для неподдерживаемого поля укажи точное действие в интерфейсе и статус. Передай факты модерации и запуска отдельно от плана.
